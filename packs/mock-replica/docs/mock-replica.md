# Mock replica

モック（HTML/CSS）を正として、実装を見た目で一致させるプロジェクトの知識。
[agent-loop-example](https://github.com/gghatano/agent-loop-example) で実際に踏んだものだけを書く。

## 前提
- モック（`mock/`）はデザインの正。実装をモックに合わせる。モックを実装に合わせて直さない
- モックに描かれているデータは `fixtures/` に移す。実装を fixtures で動かしたとき、モックと同じ画面になる
- `mock/` と `fixtures/` が変わっていないことは、check で機械的に確かめる（`git diff --exit-code <base> -- mock/ fixtures/`）

## VRT が見ているもの、見ていないもの
VRT（`scripts/vrt.py`）は、モックと実装を同じ Chromium・同じ viewport で撮り、ピクセル差分を数える。
差分 0 は強い条件だが、**見ているのはモックに描かれたデータ1件の見た目だけ**である。

| VRT で検出できる | VRT では検出できない（別の評価が要る） |
|---|---|
| レイアウト・余白・色・フォント | テンプレートへの値の直書き（モックと同じ値なので差分 0 になる） |
| モックと同じデータでの表記（¥・日付・ラベル） | モックに無い状態（別の状態値、0件、未知の値、長い文字列） |
| console error（実装側） | `<title>`、エスケープ漏れ、404 などの画面外の振る舞い |
| | 画面遷移・フォームの検証 |

右の列は、結合テスト（データを差し替えて全項目を完全一致で比べる）と E2E が受け持つ。`/mock-tests` を使う。

## 実際に踏んだ差
- **favicon**：モックは `file://` で開くので favicon を取りに行かない。実装は `/favicon.ico` を取りに行って 404 になり、console error が出る。`<link rel="icon" href="data:,">` で抑える
- **CSS の複製**：`mock/style.css` を実装側にコピーすると、モックの修正が実装に届かなくなる。実装からモックの CSS をそのまま配信する
- **リンク**：モックの `href="detail.html"` は、実装では `/projects/{id}` になる。リンク先は見た目に出ないので、VRT では検出できない。E2E で遷移を確かめる
- **表示ルールはモックから読む**：日付の区切り（`/`）、期間のダッシュ（`–`、en dash）、日数の数え方（両端を含む）、役割の決め方。読み取ったルールは純粋関数に切り出して単体テストを書き、`docs/mock-spec.md` に残す
- **モックが1件しか描いていない画面**：詳細画面のように1件分しか描かれていないと、ほかの状態（保留・完了）の見た目は VRT では確かめられない。結合テストで class 名とラベルを確かめる

## 評価関数を作るときの落とし穴
- 一部の項目だけを assert する結合テストは、見ていない項目の直書きを通す。利用例では誤実装24個のうち17個が通った
- 期待値は手で表として書く。実装と同じ整形関数で期待値を作らない
- 差し替え用のデータには、HTML を含む値・未知の状態・0件・同じ日・担当者が先頭にいない行・同名を入れる
- データの取得口を差し替えられるようにする（例: FastAPI の `Depends`）
- E2E は実データで動く。データを差し替えた確認は結合テストが担う
- 評価関数を作ったら `/mutate` を回す
