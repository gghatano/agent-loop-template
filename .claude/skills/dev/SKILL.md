手順の現在地は、AI の記憶ではなく `python3 scripts/phase.py` が決める。毎回そこから始める。

## 進め方
1. `python3 scripts/phase.py --json` を読む。`current` が今の段階、`action` が次にやること。
2. 下の表に従って、今の段階を1つ進める。
3. 段階ごとにコミットする（`phase N: <やったこと>`）。
4. `scripts/phase.py` をもう一度読み、次の段階へ。**人間の判断が要る段階に来たら止まる。**
5. 全段階が済んだら、何をしたかを段階ごとに報告する。

| 段階 | AI がやること | 止まる条件 |
|---|---|---|
| 2 パック | `packs/mock-replica/README.md` の「入れ方」どおりに取り込む | — |
| 3 評価のステップ | 技術（言語・フレームワーク）と `check.sh` の STEPS の案を議論に書く。パックを入れたなら、パックの標準ステップ（mock-unchanged・vrt）を含める | 議論の結論が空 |
| 4 仕様 | モックがあれば `/mock-spec`、なければ design から spec を導く。出典が変わっただけなら `/sync-spec` | design が TODO のまま（議論に書いて止まる） |
| 5 未定義 | 結論が書かれた議論を清書する（下記） | 結論が空の議論がある |
| 6 評価関数 | モックがあれば `/mock-tests`、なければ spec の規則ごとにテスト。実装がない状態で check が赤いことを確かめる | — |
| 7 実装 | check が緑になるまで実装する。画面ごとなら `vrt.py --only` を区切りにする | 同じ失敗を3回直せない |
| 8 評価を疑う | 評価関数の変更をコミットしてから、サブエージェント（テストを書いた文脈とは別）に `/mutate` を回させる。生き残りがあればテストを足して回し直す | 生き残りが仕様の穴か等価変異（議論に書いて止まる） |

## 人間の判断が要るとき
曖昧な質問で止まらない。必ず `docs/discussions/<今日>-<短い名前>.md` を `_template.md` の形で書く。
仕組み（scripts/・check.sh・評価の放免）についての問いも同じ。`.agent/BLOCKED` だけに書いて済ませない。
- `## 問い` に決めたいこと、`## 案` に選択肢と、それぞれを選んだときの影響を書く。おすすめがあれば明記する
- 1ファイルに問いが複数あるときは番号を振る（人間が「1: A、2: B」と答えられるように）
- 書いたら止まる。ヘッドレス実行では `.agent/BLOCKED` に議論のパスを書いて終わる

## 清書（結論 → 正）
人間が `## 結論` を書いた議論だけを清書する。結論が空の議論は清書しない。
1. `docs/decisions.md` に1項目（決めたこと・理由・捨てた案・見直す条件）。理由は議論から取る
2. `docs/design/` の該当の節に反映する（設定の決定なら `check.sh`・依存・CI に反映する）
3. 議論の status を `adopted`（却下なら `rejected`）にし、`decision:` に decisions.md の見出しを書く
4. design を変えたら `/sync-spec`
5. 結論が曖昧で2通りに読めるときは、清書せずに議論へ追記して止まる
