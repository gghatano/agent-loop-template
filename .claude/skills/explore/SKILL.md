`$ARGUMENTS` の観点でリポジトリを調査する。**直さない**。見つけて、AI が1件ずつ処理できる単位に割るのが仕事。

## 手順
1. 観点に沿ってコードを読み、必要なら `./scripts/check.sh` やテストを動かして観察する。
2. 見つかった問題を、1件 = 1 PR で閉じられる粒度に割る。
3. 各子タスクに、機械判定できる Done を付ける。付けられないものは「評価指標が先に要る」と明記する
   （それ自体が人間の仕事になる）。
4. 次の形で Umbrella Issue の本文を出力する。作成は人間の確認を取ってから `gh issue create` する。

```markdown
## Goal
<観点>について、見つかった問題を順に解消する

## Findings
- [ ] <子タスク1> — Done: <機械判定できる条件> — 根拠: <ファイル:行>
- [ ] <子タスク2> — Done: ...

## Needs evaluation first
- <Done を機械判定にできなかったもの と その理由>

## Order
<依存関係があれば処理順と理由>
```
